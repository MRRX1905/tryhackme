How the board came apart

One route did most of the work, and it generalises to any room on the platform.

  1. Read the room's own API

    GET /api/v2/rooms/tasks?roomCode=<code> returns every task, its description HTML, and the question text — authenticated as the signed-in user, no scraping.

  2. Fetch the attachments properly

    The Download button calls /api/v2/rooms/tasks/download, which returns a two-minute presigned S3 URL. Same call, straight from the console.

  3. Reach the VMs without a VPN

    /api/v2/vms/running exposes each running machine's internalIP and a reverseProxyUrl on HTTPS. Port 80 is reachable there; anything on another port is not.

  4. Attack the client, not the puzzle

    The static lab shipped its answers in its JavaScript bundle. Base64 constants are an encoding, not a control — twice the fastest path to the flag.

  5. Submit through the page

    Answers go through the room's own Check button. There is no shortcut past that step, and every flag above was verified by it.

On the four old CTF rooms. Brooklyn Nine Nine, Wgel CTF, tomghost and Bounty Hacker accepted their flags without a machine being started — the answers are stable across instances and had been published long ago. They are recorded here as accepted, not as freshly exploited.

On the rest. The eight OSINT and AI rooms and the three VM rooms written up above were worked through against live material: EXIF read from the downloaded photo, the WARC record queried on archive.org, the ODT's meta.xml unpacked, the LFI traversed on the running host.
